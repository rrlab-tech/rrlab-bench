## 关键发现

### 1. Grok 4.5 = 出乎意料的效率冠军

6 轮、22 秒、1.9 万 token 完成 agent 任务，价格 ¥0.31/次。在保持 FRR=0% 的前提下，速度是第二名的 3 倍。这解释了 xAI 在 agent 赛道的口碑——不是炒作，数据支持。

### 2. Kimi K3 thinking=low 是本次最大变量

原 thinking=max 模式 Kimi 在 4 模型测评中排名靠后（token 多、价格高）。将 thinking 调至 low 后：
- 每个场景 token 减少 **52%~74%**
- 耗时减少 **11~130s**
- 从倒数跃升至 **#2**

证明了 **thinking 级别是用户可调的有效杠杆**——不是越低越好，但模型提供了这个选择，善用可以大幅降本。

### 3. 为什么最后换成了 DS V4 Pro 作为主力

虽然 Grok #1、Kimi #2，你选 DS V4 Pro（#3）作为主力——决策合理：
- ¥0.17/次，比 Kimi 便宜 63%，比 Opus 便宜 96%
- 官方直连稳定性好（Kimi 重跑时遇到 429 限流）
- DeepSeek 生态完整性（自有 API + 工具链 + 社区）
- 48s 的耗时在交互式使用中可接受

这个选择本质上是在"效率分数"和"成本 × 稳定性"之间的权衡，#3 选 #3 = 正确的工程判断。

### 4. Opus 表现分化但样本不足

Opus 4.8 7 轮排 #4，但 Opus 5 MAX 21 轮垫底——原因可能是 MAX 模式过度推理（单次消费 22.8 万 token，是 Grok 的 12 倍）。但仅 3 个样本，这个结论不稳定。如果后续要增加 Opus 样本量，可以重点对比 4.8 vs MAX 在 agent 场景的实战差异。

### 5. FRR 全 0% = 场景需要升级

当前 3 个场景对所有 9 模型 FRR=0%，说明题目太简单。探针已经证明了"构造有区分度的场景"是可行的（write-only-policy 让 DS V4 Pro FAIL）。下一版场景池应该从探针方法论吸取经验——定向构造需要特定能力才能通过的场景，而不是通用 coding task。

## 方法论备注

- **排名算法**：效率综合分 = 回合 × 0.4 + Token/1000 × 0.3 + 耗时 × 0.3，无 FRR 加权（全部 0%）
- **为什么不用纯费用排名**：费用受定价策略影响（Opus 贵不是它能力差），综合效率更客观
- **采样不足警告**：Opus 系列 3 场景各 1 次跑，9 次的数据勉强可用但不够稳定。如果要严肃引用 Opus 排名，建议每场景 ≥3 次重复
