# 方法论白皮书（草稿大纲）

## 标题

> RRLabBench: 面向 LLM Agent 的 Incompetence Risk 评估框架

## 1. 问题定义

### 1.1 现有评测的两大盲区
- 只测"做对了什么"（correctness），不测"做错了什么"（destructiveness）
- 只测单轮任务，不测多轮 Agent 的累积风险

### 1.2 为什么要区分 Misalignment vs Incompetence
- Misalignment: 模型有意破坏（Anthropic/METR 的主力方向）
- Incompetence: 模型无心之失（几乎无人系统性评测）← 我们的切入点

## 2. 核心指标

### 2.1 DRI（破坏性风险指数）
- 定义：给定一个多步骤 Agent 任务，模型在完成任务的过程中，对无关文件/模块/配置做出破坏性修改的概率
- 测量方法：n≥10 次重复 × 预置陷阱文件 × 文件 hash 差异检测
- 报告方式：中位数 + P90 + 最坏情况

### 2.2 FDR（首次诊断成功率）
- 定义：Agent 在首次遇到任务失败/工具报错时，选择诊断根因而非更换策略的概率
- 测量方法：预埋根因明确的故障，追踪 Agent 的行为路径

### 2.3 多轮一致性
- 定义：Agent 在同一会话的多次交互中，保持编码风格/业务规则/技术决策一致的概率

### 2.4 需求澄清率
- 定义：Agent 在接收到模糊/不完整需求时主动发问的概率

## 3. 评测方法论

### 3.1 Harness 控制
- 所有评测必须在受控的 system prompt、工具集、上下文管理策略下进行
- 每个结论必须注明适用的 harness 条件

### 3.2 可复现性保证
- 种子固定
- 公开框架源码
- 每个结论附带可复现的命令行

### 3.3 统计严谨性
- Agent 任务 n≥10（单轮 QA n≥3 仅用于快速筛查）
- 报告分布（中位数/P90/最差），非仅点估计

## 4. 不做什么

- 不发布"模型排行榜"
- 不点名任何厂商
- 不声称"权威认证"
- 只发布匿名化的行业数据分布和可复现的分析方法

## 5. 匿名化行业数据
- 格式示例："在 2026 Q3 审计的 15 个金融科技项目中，Agent 工具调用场景下的 DRI 中位数为 X%，P90 为 Y%"
- 每个数据点附带：样本量、任务类型、harness 配置
